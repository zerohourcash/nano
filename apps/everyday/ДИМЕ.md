# MeshKeeper — передача Диме

## Что это

LAN-версия учёта оборудования для лабораторий / стройки / мастерских.

- UI: React 19 + Vite + tRPC-клиент (протокол HTTP batch + superjson `{json}`).
- Узел: Rust (`backend/`, axum + rusqlite), порт **8080**.
- Журнал: append-only аудит-лог операций (кто, что, когда, причина).
- База: SQLite WAL, `data/meshkeeper-rs.db`.
- Приглашение в группу: QR с токеном, `/join?token=`.

Интерфейс говорит с узлом как с tRPC: `POST /api/trpc/{procedure}?batch=1`, тело `{"0":{"json":{...}}}`, ответ `{"result":{"data":{"json":...}}}`. Сессия — непрозрачная HttpOnly-cookie `mk_session` (SameSite=Strict); старые `x-user-id` / `mk_user` больше не принимаются. Мутации требуют same-origin заголовка `Origin`.

## Готовые сценарии

- Регистрация владельца и вход по телефону+паролю
- QR-приглашение и `auth.join` / `auth.joinRegister`
- Каталог поштучно, массовая выдача `transfers.takeMany`, возврат
- Срок возврата `dueAt`
- Неисправности `items.reportFault` / `resolveFault` (блок выдачи)
- Заявки на правку `items.requestChange` / `decideChange`
- Чат группы `chat.list` / `chat.send`
- Инвентаризация, история операций, отчёты CSV/XLS/PDF
- Индивидуальные `roleRights`

## Как запустить

См. `КАК_ЗАПУСТИТЬ.md`. Команда: `bun run dev` в `C:\mkapp`.

## Где что лежит

Запись в журнал: `backend/src/ledger.rs` → `append`.  
Диспетчер процедур: `backend/src/api.rs` → `dispatch`.  
Схема: `backend/src/db.rs`.
Обмен с сервером: `backend/src/sync.rs` и `upstream_loop` в `backend/src/main.rs`.

UI трогать не обязательно, если ответы остаются в том же tRPC-конверте.
