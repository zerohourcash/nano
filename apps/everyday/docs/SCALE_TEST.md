# Масштабный тест mesh

## Что проверяется

`npm run scale:test` запускает 100 настоящих экземпляров production Rust-бинарника.
У каждого процесса собственные TCP-порт, SQLite-база, node ID и два worker-потока.
Это не симуляция записей внутри одного процесса.

Топология разреженная: кольцо плюс резервные связи с шагом 10. Каждый узел имеет
не более четырёх прямых соседей. Такая схема сохраняет связность при части
отказов и не создаёт O(N²) соединений.

Сценарий проверяет:

1. запуск и health всех процессов;
2. распространение организации и аккаунта с root на 100/100 баз;
3. офлайн-вход на удалённом узле;
4. подписанное сообщение и выдачу оборудования на удалённом узле;
5. доставку событий к root с сохранением Ledger V2 и device-proof;
6. работу после одновременной остановки 10 процессов;
7. перезапуск этих процессов на прежних базах и догон журнала;
8. отсутствие дублей, соблюдение лимита peers, RSS и объём обмена.

Отдельный `npm run mesh:test` разрывает все соединения одного узла, выполняет
на нём подписанные выдачу инструмента и отправку сообщения, дожидается
нескольких неудачных фоновых попыток, а затем возвращает соседей с прежними
базами. Операции автоматически доставляются без ручного `pullNow` и появляются
на каждой ноде ровно один раз. Это проверяет устойчивую отложенную доставку
store-and-forward, а не только кратковременный сетевой сбой.

Среда контрольного запуска: Linux-контейнер, 20 ГБ RAM, loopback transport,
release-бинарник, отдельная SQLite-база на узел.

## Как повторить

```bash
npm run build:server
npm run scale:test
```

Для быстрого диагностического запуска количество можно уменьшить, но такой
прогон не является доказательством требования 100 узлов:

```bash
MESHKEEPER_SCALE_NODES=10 npm run scale:test
```

## Границы результата

Тест доказывает масштабирование числа узлов на небольшом рабочем журнале. Он не
доказывает приемлемый трафик для многолетней истории с миллионами вложений:
текущий HTTP transport передаёт полный прикладной snapshot. Перед эксплуатацией
такого объёма нужен отдельный soak-тест с целевым профилем данных и переход на
инкрементальный обмен по frontier/hash. BLE, Wi‑Fi Direct и LoRa также требуют
собственных тестов пропускной способности и фрагментации пакетов.
