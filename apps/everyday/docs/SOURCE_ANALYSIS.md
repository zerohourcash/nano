# Анализ двух исходных проектов

## Что использовано

1. **Ychet_oborudovaniya / MeshKeeper** — рабочая кодовая база: React/Vite,
   Rust/Axum, SQLite, роли, выдача и возврат, инвентаризация, аудит и
   offline-first синхронизация.
2. **FaceKit snapshot** — 13 сохранённых HTML-экранов. Это не исходный код и
   не дамп базы. Из него взяты терминология, состав карточки и рабочие
   сценарии; минифицированные скрипты FaceKit в проект не копируются.

## Объединённая предметная модель

| FaceKit | Everyday |
| --- | --- |
| ТМЦ и карточка | `items`, фотографии, документы и комментарии |
| Проекты | объекты работ (`building_sites`) |
| Склады | `storages` |
| Передать / принять | `transfers` и подтверждение получателем |
| Согласование | заявки на изменение (`change_requests`) |
| Реестр инвентаризаций | `inventory_sessions` и `inventory_results` |
| Контроль сроков | `due_at`, поверка и уведомления |
| Роли | права пользователя отдельно в каждом рабочем пространстве |
| Поля FaceKit и внешние ID | `source_system`, `external_id`, `metadata_json` |

`metadata_json` сохраняет без потери поля, которых нет в основной схеме:
компанию-владельца, резерв, амортизацию, срок службы и аренды, валюту, тип,
ярлыки, комплектность, поставщика, реквизиты документа, доставки, заявки и
счёта, а также пользовательские поля. Размер ограничен 64 КБ на карточку.

## Ограничение исходных данных

HTML-снимок содержит только то, что было видно на экране в момент сохранения.
Он не доказывает полноту записей на сервере FaceKit. Команда ниже извлекает
весь видимый текст, сохраняет порядок и SHA-256 каждого исходного HTML:

```bash
npm run import:facekit -- ../facekit/1
```

Результат пишется в `data/import/facekit-snapshot.json` с правами `0600`.
Каталог `data/` исключён из Git, потому что снимок содержит персональные и
организационные данные.
