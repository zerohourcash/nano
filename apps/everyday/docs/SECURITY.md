# Модель безопасности

## Граница доверия

Пользователь браузера аутентифицируется непрозрачной HttpOnly-сессией.
Каждый mesh-узел синхронизации является доверенным участником: доступ к
`MESHKEEPER_SYNC_TOKEN` фактически даёт доступ к синхронизируемым рабочим
данным и хешам паролей для офлайн-входа. Такой токен нельзя выдавать обычному
пользователю или встраивать во frontend/APK.

## Защита backend

- Argon2id для новых паролей; длина нового пароля 12–128 символов.
- Сессионный токен хранится в БД только как SHA-256, cookie — HttpOnly,
  SameSite=Strict и Secure в production.
- Изменяющие browser-запросы требуют same-origin `Origin`.
- Все запросы ограничены 32 МБ; `metadata_json` — 64 КБ.
- CSP, запрет iframe/MIME sniffing, строгая referrer-policy и Permissions-Policy.
- API и sync-ответы получают `Cache-Control: no-store`.
- Не-loopback bind требует secure-cookie; каждый peer синхронизации требует HTTPS.
  Незашифрованный HTTP разрешается только для loopback или явной тестовой
  настройки `MESHKEEPER_ALLOW_INSECURE_SYNC=1`.
- Активные QR-приглашения по умолчанию не передаются в журнале синхронизации.
  Совместимость включается только через `MESHKEEPER_SYNC_INVITES=1`.
- Критические операции требуют Ed25519-подпись зарегистрированного устройства
  над методом, путём, временем, nonce и SHA-256 тела. Nonce одноразовый,
  отозванные устройства отклоняются до начала транзакции.
- Ledger V2 подписывается ключом узла, связывается `prev_hash` и использует GUID
  организации, пользователя и объекта. Доказательство устройства сохраняется
  внутри события и повторно проверяется при старте и при импорте sync-журнала.
  Невалидный импорт откатывается целиком через SQLite savepoint.
- URL peer проверяется: запрещены credentials, path, query и fragment. HTTP
  разрешён только для loopback либо явной изолированной тестовой LAN.

## Production checklist

1. TLS завершается на nginx/Caddy, backend слушает `127.0.0.1`.
2. `MESHKEEPER_COOKIE_SECURE=1`, sync-токен сгенерирован CSPRNG (32+ байта).
3. Реальные `.env`, БД, бэкапы и FaceKit-импорт не находятся в Git.
4. Локальные диски зашифрованы; для переносимого узла используется сборка
   SQLCipher и отдельный `MESHKEEPER_DB_KEY`.
5. Запускаются `npm run verify`, резервное копирование и проверка восстановления.

## Не обещается

Защитные меры снижают риск, но не делают систему «абсолютно безопасной».
Перед хранением паспортных, биометрических или иных особо чувствительных
данных необходимы отдельная модель угроз, аудит и требования применимого
законодательства.
