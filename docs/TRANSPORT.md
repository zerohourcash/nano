# Транспортно-независимый mesh-протокол

Ledger не доверяет транспорту. Единица обмена — UTF-8 JSON `{"events":[Event...]}`; каждое событие содержит Ed25519-подпись, BLAKE2b-256 идентификатор, публичный ключ, ссылку на предыдущее событие автора и ссылку на предыдущую операцию с предметом. Приёмник сначала проверяет подпись и обе причинные ссылки и только потом сохраняет запись.

## Уже работает

- IPv4 LAN: обнаружение через UDP multicast `239.42.78.71:47871`, сверка через HTTP `/api/events`.
- Любая IP-сеть: `POST /api/sync` с адресом известной ноды.
- Полностью разорванная сеть: экспорт/импорт JSON из PWA (флешка, AirDrop, мессенджер, QR-передатчик с разбиением на части).

## Контракт адаптера

Bluetooth Mesh, BLE GATT, Wi-Fi Direct, WebRTC DataChannel, LoRa/радиомодем, NFC и последовательный порт реализуют один контракт:

1. Обменять `HELLO { protocol: "nano-inventory/1", nodeId, frontiers: { actor: { seq, id } } }`.
2. Запросить неизвестные идентификаторы `WANT { ids[] }`.
3. Передать пакет `EVENTS { events[] }`, допускается дробление.
4. Каждый фрагмент: `messageId(16) | part(2) | total(2) | payload | crc32(4)`. CRC нужен лишь для ошибок канала; безопасность обеспечивает подпись события.
5. Повторять доставку до `HAVE { ids[] }`. Дубликаты безопасны.

Для BLE практичный профиль: отдельная service UUID, write-without-response для фрагментов и notify для ответов; размер фрагмента равен согласованному ATT MTU минус 24 байта. Для Bluetooth Mesh события следует передавать как vendor model messages с тем же фреймингом. Мобильной оболочке достаточно отдать собранный JSON в `POST /api/events` или напрямую вызвать `Ledger.import`.

Транспортное шифрование (TLS, BLE link encryption) желательно для конфиденциальности, но не заменяет подписи. Текущий прототип обеспечивает целостность и авторство, но содержимое пакета не шифрует.
